# prose-adapter

모델은 그대로 두고, **사용자가 고친 글로 배우고 검증되는 외부 문체 어댑터**. LoRA처럼 갈아 끼우지만 가중치가 아니라 규칙 문서(`vN.md`)가 바뀐다.

## 핵심: 관문 점수 = 교정 재현

사용자가 실제로 고친 초고 일부를 숨겨 둔다. 새 어댑터 후보로 **그 초고를 다시 퇴고**시키고, 결과가 사용자의 실제 교정본에 얼마나 더 가까워졌는지 잰다.

```
gain = 유사도(어댑터가 고친 글, 사용자 교정본) − 유사도(손대지 않은 초고, 사용자 교정본)
```

내용이 고정된 같은 초고를 고치므로 "문학성 90점" 같은 LLM 심사 취향이 끼지 않는다. 후보는 검증 세트에서 기존 버전보다 gain이 높고 진 항목이 이긴 항목보다 많지 않을 때만 새 버전이 된다(SkillOpt식 제한 편집 + 검증 채택).

## dot 하네스에서 가져온 것

| dot (`harness/rules/learning.md`) | prose-adapter |
|---|---|
| 판정 원본 `verdicts.md` (추가만) | `corrections.jsonl`: 초고 → 사용자 교정 한 쌍 = 판정 한 건 |
| 보고 전에 예측을 적고 적중률을 잰다 | 초고마다 "사용자가 고칠 문장"을 예측 → 실제 고친 문장과 비교(정밀·재현) |
| criteria 한 줄 = 가설 + 받치는 판정 번호, 판정 하나면 '관찰' | 규칙마다 근거(교정 id), 1건 = 관찰(집필에 안 넣음), 2건 이상 = 가설, 관문 통과 = 채택 |
| 고친 기준은 판정을 모르는 새 워커로 검사, 적중이 줄면 안 고침 | 학습용·검증용 분리, 검증 gain이 늘 때만 새 버전 |
| 경로 점수 | 규칙별 예측 기록: 예측에 쓰인 수, 실제로 고쳐진 수 → 헛짚는 규칙은 삭제 후보 |
| 원문 불변, 입구 최신, 이력 추가만 | `vN.md` 불변 · `CURRENT` 입구 · `HISTORY.md` 추가만 · state 이력 보존 |
| 한 번의 감상을 상시 지시로 만들지 않는다 | `status_for`: 근거 1건으로는 집필 규칙이 되지 못하게 코드가 막는다 |
| 프로젝트 ↔ 공용 층 분리 | 작품 상태(`works/<작품>/state.md`) ↔ 어댑터(여러 작품에 통하는 문체) |

## GPT 제안 대비 더한 것
- 주관 평가 문제의 해법: 사용자의 실제 교정본을 정답으로 쓰는 교정 재현 점수(위).
- 예측 적중: 어댑터가 사용자 취향을 "아는지"를 매 초고마다 잰다. dot의 적중률과 같은 자리.
- 작품 상태를 세계 사실 / 인물별 믿음(오해 표시) / 작가 계획 / 미회수 복선 / 연표로 분리(NarraWorld식). 확정 본문으로만 갱신.
- 세 갈래 비교 실험이 명령 하나: `pa eval webnovel v0 v1 v5` = 기본형 · 수동 특화(사용자 스킬) · 학습 특화.

## 쓰는 법

```bash
python3 pa.py init webnovel --from seeds/webnovel-manual.md   # 사용자 스킬을 옮긴 시작점
python3 pa.py write webnovel "회귀한 검사가 사형과 다시 마주친다" --work 회귀검사
# data/drafts/<id>.md 를 직접 고친다
python3 pa.py collect
python3 pa.py learn webnovel
python3 pa.py stats webnovel
```

LLM은 `claude -p`를 도구·사용자 설정 없이 단발로 부른다(`PA_MODEL`, 기본 sonnet). 호출마다 비용이 `data/calls.jsonl`에 남는다. 데이터 위치는 `PA_HOME`(기본 `data/`).

## 한계
- 교정이 적으면 검증 세트가 작아 같은 세트에 맞춰질 수 있다. `--repeats`로 흔들림을 줄이고, 교정이 쌓이면 검증 세트가 자연히 커진다.
- 재는 것은 "이 사용자의 교정에 얼마나 가까운가"다. 작품의 흥행이나 절대 품질이 아니다.
- 가상 작가 시연은 기계가 도는지의 증명이다. 실제 사용자의 미묘한 문체는 실제 교정으로 다시 확인해야 한다.
